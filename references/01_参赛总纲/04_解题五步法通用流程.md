# 解题五步法 · 通用流程

> 核心理念：建模是"读懂问题 → 拆解 → 数学表达 → 求解验证 → 讲清楚"的过程，不是堆模型。

## 五步法（对应论文章节）

```
① 读题理解  → 问题重述 + 问题分析
② 数据文献  → 数据预处理 + 模型假设
③ 建模       → 模型建立（分问写）
④ 求解验证  → 模型求解 + 结果分析
⑤ 写作升华  → 摘要 + 灵敏度 + 评价 + 附录
```

## 第一步：读题（开赛 0-2h，决定成败）

**选题决策**（15-30 分钟，别超 1h）：
1. 熟悉度（统计强 → C 题优先）
2. 数据量（有附件 → 数据题概率大）
3. 开放度（开放题容错高、评分弹性大）
4. 工作量（数问数，问多=工作量大）

**定题后立即公告，全队禁止回头**——摇摆是最大时间杀手。

**精读题目**每问三件事：要什么输出（定类型）、给了什么（定方法）、隐含要求（"注"里藏分点，如 NIPT"直接聚类不好"）。

## 第二步：数据与文献（2-6h，并行）

- 数据侦查：读入→看维度/类型/缺失/异常→画分布/箱线/热力图→记录"数据故事"。
- 文献调研：搜关键词+模型/方法；重点找往年同类获奖论文；AI 总结 3-5 篇核心方法→人工判断。目标 2h 内定 1-2 条候选路线。

## 第三步：建模（核心攻坚）

- 先搭框架：解题流程图 + 每问候选模型 A（主）+ B（对比）+ 模型假设。
- **由简到繁迭代**：先跑通最简模型 → 检查合理性 → 逐步加复杂度 → 每步留结果。
- 第一天结束前必须有能跑出数字的模型；第二天再上高级模型/对比/灵敏度。
- **最忌憋大招**：第三天模型还没跑通 → 论文没东西写。

## 第四步：求解与验证

- 固定随机种子，保证可复现；关键数字记录来源。
- 必做验证：误差指标 + 残差分析 + 灵敏度（±5%/±10%）+ 稳健性 + 多模型对比。

## 第五步：写作与升华（"三分建七分写"）

- 摘要最后写（占 20-25%）；图 > 表 > 文字；每段服务一个观点；用数学语言。
- 写作者必须真懂模型（不懂让建模者口述）。

## 常见失败模式与预防

| 失败模式 | 预防 |
|---|---|
| 选题摇摆超 1h | 定死时间线，队长拍板 |
| 模型憋到第三天没跑通 | 第一天必须跑通简单版 |
| 论文写不完/摘要没时间 | 第二天晚开始写初稿 |
| 摘要空话无数字 | 强制填"方法+数字结果" |
| 没有灵敏度分析 | 第二天预留 2h 专门做 |
| 图表无编号/公式不规范 | 写作手用检查清单逐项过 |

## C 题（数据题）专项套路

近 5 年规律：**真实业务数据 + 3-5 个递进问题**。标准打法：
1. 问 1 = 关系/规律挖掘（相关 + 回归 + 显著性，注意非线性）
2. 问 2 = 优化决策（问 1 规律作约束 → 规划/优化，注意分组机制）
3. 问 3 = 递进（加多因素/复杂约束 → 模型升级）
4. 问 4 = 分类判定/扩展（注意阈值与误判权衡，勿盲目套 ML）
5. 开放问 = 新问题 + 模型推广（体现深度）
