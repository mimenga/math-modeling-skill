# 知识库与蒸馏协议

## 知识库结构（与实际一致）

```
skill/
├── SKILL.md
├── README.md
├── scripts/                  # 现成代码模板库
└── references/
    ├── INDEX.md              # 知识索引（全目录）
    ├── 01_参赛总纲/
    ├── 02_建模方法库/
    ├── 03_统计与数据挖掘/
    ├── 04_论文写作/
    ├── 05_优秀论文精华/
    ├── 06_NIPT_C题专题/
    ├── 07_参考书目/
    ├── 08_协作与进度/
    └── 09_2025A题专题/
```

## 知识卡片格式（轻量，与现有文件一致）

新资料入库统一用「主题笔记」格式，**不强求严格字段**，与现有文件风格保持一致即可：

```markdown
# {主题}

> 来源：{书目/真题/论文/蒸馏} ｜ 关键词：{3~5 个}

## 核心内容
（自由组织，200~500 字：是什么、怎么用、关键公式/步骤）

## 适用场景
（可选：什么情况用；什么情况不适用）

## 注意事项
（可选：陷阱、易错点、边界）
```

要点：
- 文件名用 `{编号}_{主题}.md`，编号接续所在目录现有最大编号（如 `04_论文写作/07_xxx.md`）。
- 首行 `# {主题}`，正文用 `##` 分节；有出处就在标题下加一行 `> 来源 / 关键词`。
- 同主题已有文件则**合并更新**，不另建新文件。

## 入库流程

1. 判断资料归属目录（01~08 哪一类）。
2. 按 `{下一编号}_{主题}.md` 命名写入对应目录。
3. 更新 `references/INDEX.md` 登记新文件。
4. 报告：文件路径 + 核心要点一句话。

## 检索规则

- 收到建模请求先**用 Grep 在 `references/` 按关键词/子问题检索**，只读命中的文件。
- 命中卡片优先基于卡片内容给思路，标注"依据知识库：{文件名}"。
- 无相关内容退回通用知识，提醒"可考虑补充"。

## 蒸馏协议（从外部来源提炼）

**原则：提炼而非搬运**——不复制他人原文，只提取可复用的方法论/工作流/技巧/陷阱。

**流程**：
1. 读取来源（GitHub skill、网页、PDF、zip）
2. 价值判断：是否覆盖新主题？是否更优？是否与国赛直接相关？
3. 提炼卡片（来源类型=蒸馏，记录出处）
4. 标注溯源 + 蒸馏日期
5. 汇报：提炼了哪些、存到哪、建议何时用

**判断规则**：吸收通用方法论/可复现工作流/实用代码模板/反直觉陷阱；不吸收无关细节/宣传内容/无法验证的说法；改造后吸收（调整为自身工作流）。

**注意事项**：尊重许可证与版权，只提炼思想与流程；蒸馏结果在真实题目验证一次后再视为可靠。

## 真题专题卡生成流程（新赛季题目公布后）

新赛季题目公布后，按 `06_NIPT_C题专题/` 的框架为新题生成专题目录，实现专题层复用：

1. **建目录**：`references/{下一编号}_{年份}{题号}专题/`（如 `06_NIPT_C题专题/`、`09_2025A题专题/`；旧专题目录原地保留，不删除——历史专题仍可作同类题参考）；
2. **第一张卡：评阅要点与通用法则**（参照 `06_NIPT_C题专题/01`）——收集官方评阅要点/评委访谈/赛后复盘，提炼"评委要什么 / 不要什么"；
3. **第二张卡：逐问解法路线**（参照 `06_NIPT_C题专题/02`）——按问拆解，每问给可执行步骤（方法公式级粒度），附"写作提示"；
4. **更新**：`references/INDEX.md` 登记新目录；`01_参赛总纲/00_当前赛况配置.md` 的"当前赛题专题"指向新目录；
5. **验证**：解法路线先在数据上试跑一问，跑通后再定稿。

原则：**通用方法沉淀在 02/03（方法库），专题只放该题特有的机制与路线**——换题时方法库零改动，只换专题层。
